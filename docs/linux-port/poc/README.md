# POC atlas

Proofs-of-concept, experiments, and cross-cutting **compositions** — things we
tried and (often) proved, but that are **not leaf product features and not
framework subsystems**, so they don't belong on the measured features board
(ADR-0011 / ADR-0014) and aren't decisions (the ADR atlas). This atlas tracks
their **maturity** and **where they went**.

## Why this is separate from the features board

The features board is **generated by measurement**: `capslib.py` parses the
Swift dispatchers and `features-board.py --check` fails on verbs that don't
exist in the source. An in-flight POC has **no verbs to measure yet**, so it
physically cannot live there. And a *proven composition* (e.g. browser
automation × claude-teams) is a workflow **over existing verbs**, not a new
verb. So this atlas is **authored** — like the ADR atlas — not measured.

## Maturity model

The `status:` front-matter field:

| status | meaning |
|---|---|
| `idea` | noted, not yet attempted |
| `wip` | actively being built / tried |
| `proven` | demonstrated to work; not yet adopted into the product |
| `adopted` | wired into the product — see `adopted:` for the feature slug |
| `shelved` | tried, then parked (record the why) |

**Graduation is not a move.** When a POC is wired in and becomes measurable,
author a `features/` page and the generator picks it up automatically. Set this
POC's `status: adopted` and `adopted: <feature-slug>` — the page **stays** here
as the origin record (how the feature came to be). Nothing migrates; the board
auto-detects the real thing. Same spirit as ADR-0011: **authored intent →
measured reality, joined by a slug.**

## Page front matter

```
title:        short name
area:         same vocab as the features board (browser, terminal, …) — cross-links
kind:         composition | experiment | probe
status:       idea | wip | proven | adopted | shelved
linux / mac:  where it has been demonstrated (proven / untested / n-a)
substrate:    the feature(s) / harness it builds on
adopted:      feature slug once graduated (else "none")
evolves_to:   what it could become
```

No unique-vs-macOS column is enforced here — uniqueness is a *product*
comparison (that lives on the features board). A POC only records where it has
actually been **run**.
